Scope 2: tooling
- oxfmt.config.ts follows the monorepo's exported formatterOptions/defineConfig
  shape, retaining existing root defaults: double quotes, semicolons, trailing
  commas, width 100, no import reordering. Docs now use the same settings.
- Oxfmt 0.74.0 runs via fmt/fmt:check with an explicit config path. Vite+ 1.2.0
  interprets -c formatter configs as Vite configs with a fmt field, so direct
  Oxfmt is used for this standalone formatter config, as in the reference repo.
- .oxlintrc.json centralizes lint rules for root/docs. vp lint gets the explicit
  -c path; vite.config.ts also extends it. This avoids the empty lint configuration
  selected by Vite+ when a Vite config has no lint field. Prettier ignore/configs
  and direct ESLint/Prettier runner dependencies are absent. The Convex and
  stylistic ESLint-named packages are JS plugins loaded by Oxlint, not runners.
- options.typeAware works for native Oxlint rules. The Convex JS plugin uses AST
  fallback because ESLint parser services are unavailable; its diagnostics say so.
- Convex rules cover every **/component/** source: args validators, object syntax,
  explicit table IDs, no query filter/collect, no process.env, index/cycle checks.
  The existing blank-line rule is retained. Generated/dependency/build/cache,
  protected spec paths, vendored skills and generated registry output are ignored.
- Fixed 35 table-ID calls (15 meter, 20 sandbox) with their existing typed table
  names, new lint-covered registry/docs spacing, one unused registry declaration,
  redundant unknown union and type-only/stringification lint findings.
- Kept extraction by_file with a local documented no-duplicate-indexes suppression:
  its creation-time order differs from by_identity's backend order. No schema or
  ordering behavior was changed. Kept intentional await boundaries with local
  documented suppressions. Tests alone permit unbound spy matcher references
  and JavaScript's default lexical sort.
- A third-run failure exposed an existing parallel-effect assertion in the hook
  test: its note/result ordering assertions passed, but concurrent tool effects
  finished in reverse order. The final effect assertion now compares a sorted
  copy, preserving multiplicity and requiring exactly the same two effects.
- Return-validator lint remains deferred: @convex-dev/eslint-plugin 5.0.0 has no
  such rule. Existing validators are unchanged; review remains required.
- check includes formatting, lint, library/test types, a negative/positive Convex
  args-validator gate in all four component directories, and docs checks.
- docs/site uses Vite+ and the same root formatting/lint config. Its typecheck
  generates route types directly through Router Generator, with no prior build.
  example/ is absent on this branch and was skipped.
