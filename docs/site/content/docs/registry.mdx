The registry ships four [tools](/docs/tools): `todo`, `goals`, `ask-user` and
`continue-budget`. shadcn copies their source into `convex/agevexTools/` and
installs `ai`, `convex` and `zod`. The host must already have `agevex` and a
TypeScript `components.json` with `"tsx": true` so shadcn preserves types.

## Install

Start this site with `bun run dev` from `docs/site`, then install the items
you need. Replace the origin when using a deployed registry:

```sh title="Terminal"
bunx shadcn add http://localhost:3000/r/todo.json
bunx shadcn add http://localhost:3000/r/goals.json
bunx shadcn add http://localhost:3000/r/ask-user.json
bunx shadcn add http://localhost:3000/r/continue-budget.json
```

Todo and goals include host table snippets. Merge `todoTables` and `goalTables`
into your existing `convex/schema.ts`; installation does not overwrite it.
`ask-user` and `continue-budget` need no item tables. Follow each item's registration and
authorization notes before use.

`@agevex` is a provisional namespace. Configure it in the host's
`components.json` before using namespaced install commands:

```json title="components.json (registries entry)"
{
  "registries": {
    "@agevex": "http://localhost:3000/r/{name}.json"
  }
}
```

Then `bunx shadcn add @agevex/todo` resolves to the same source. Community
registries can use the same shadcn item format.

## Rebuild and verify

From the repository root:

```sh title="Terminal"
bun run registry:build
bun run test:tools
AGEVEX_TOOLS_INSTALL_NETWORK=1 bun run test:tools
```

The build synchronizes registry identity from `site.config.ts`, runs
`bunx shadcn build` and writes output committed under `docs/site/public/r/`.
The docs production build also regenerates these files.

Tests type-check all payloads and merged schemas in an independent host.
CLI smoke tests run offline by default and skip clearly if shadcn needs an
uncached dependency or remote catalogue. The opt-in command exercises real
installs with network access and type-checks the installed source and schemas.
