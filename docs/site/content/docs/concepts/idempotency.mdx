## Request and effect identities

`open` and `send` dedupe by subject and request key. Managed once-tools use
`receipts.effects.begin` and `receipts.effects.complete`. Their scope hashes
the subject, thread and tool name; the key hashes the custom key or tool-call id.
An input fingerprint detects changed input under the same key.

| Receipt state         | Admission behavior                                                  |
| --------------------- | ------------------------------------------------------------------- |
| Missing               | Create a running claim and run once                                 |
| Running, lease live   | Return `running`                                                    |
| Done or failed        | Replay the stored result                                            |
| Expired or unknown    | Return `unknown`; only an explicitly repeat-safe effect can reclaim |
| Different fingerprint | Deny with `KEY_CONFLICT`                                            |
| Stale execution fence | Refuse the managed write                                            |

Completion checks the claim, lease and execution fence. Expiration does not
prove that a provider did no work. Inspect the provider outcome before deciding
whether to issue a new operation.

## Define a managed tool

```ts title="convex/echo.ts"
import { defineOnceTool } from "agevex";
import { z } from "zod";

export const echo = defineOnceTool({
  name: "echo",
  input: z.strictObject({ text: z.string().max(1000) }),
  run: ({ text }, tc) => {
    tc.signal.throwIfAborted();
    return { text, threadId: tc.threadId };
  },
});
```

Add `echo` to a managed Agent's `tools`. The runtime binds the receipt and
trusted `ToolContext`; calling its unbound execute throws
`MANAGED_TOOL_CONTEXT_REQUIRED`. `run` returns a Convex-serializable value.
A thrown tool body saves a sanitized `TOOL_FAILED` result when its claim is valid.

`tc.promptMessageId` identifies the native request this turn answers (the task
message in a child). Core supplies it from the trusted turn claim, including
when executing an approved tool; it is optional for contexts without a prompt.
Use that id directly when associating an effect with its request.

`key(input, tc)` can define an effect identity across tool calls. Keep it
stable. `repeatSafe` defaults to false. `leaseMs` defaults to ten minutes;
the registration default may be raised up to one day. A tool-specific
`leaseMs` must be positive. Results must fit 64 KiB; return a
storage id for larger content. Receipts retain a seven-day replay window and
are purged in bounded batches.

## Structured tasks

`defineTask` declares input/output schemas, a prompt, optional system
`instructions` (part of the payload fingerprint) and an optional model.
`runTask(hc, task, input)` inside a managed hook inherits the receipt context,
attribution and fence. Standalone `runtime.runTask(ctx, task, input, options)`
requires a stable `key`, server-derived `attribution` and a model on the task
or options. One repair re-ask is allowed for invalid structured output; unknown
paid outcomes are never retried. See [slots](/docs/concepts/slots).

Sandbox and extract have their own durable claims. They do not share the core
request ledger for all module operations. Receipt fencing controls admission;
external exactly-once effects still require provider support.
