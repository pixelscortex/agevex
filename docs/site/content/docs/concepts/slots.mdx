`registerAgent` accepts four optional slots: `usage`, `budget`, `telemetry`,
and `sandbox`. Core imports only the slot contracts; each optional module adds its own
adapter. An omitted slot ignores usage, allows spending, exports no telemetry, adds no sandbox tools and passes files as native model parts.

Every managed tool receives a `ToolContext` through the AI SDK `options.context`;
a native `createTool` also gets the facts on its injected context and
`defineOnceTool` as its second argument. `subject`, `rootThreadId`,
`threadId`, `runId`, `agent` and `toolCallId` are non-empty strings of at most
128 UTF-8 bytes; `nativeToolCallId` preserves the provider id, while `signal` is an AbortSignal.

`promptMessageId?: string` is the trusted native request anchor returned by
the component's turn claim, never model input. For a root request it identifies
the saved user message; for a child it identifies the saved task message. Tool-step
slices and approval resumes retain that request id. Contexts without a
managed prompt may omit it. Hooks receive it too, through `HookContext`.

```ts title="convex/budget.ts"
import type { BudgetSlot } from "agevex";

const allowedSubjects = new Set(["replace-with-your-auth-subject"]);
export const budget: BudgetSlot = {
  async check(_ctx, { subject }) {
    return { allowed: allowedSubjects.has(subject) };
  },
};
```

This fixed allowlist is a minimal policy. For a spending cap, read your own ledger.
See [Recording usage in your app](/docs/concepts/recording-usage).

## Usage

`usage.record(ctx, event)` receives each saved model step, trusted attribution,
token usage, exact native message id and provider response id when available.
The app owns deduplication, pricing and reconciliation. Callback failures mark
the run partial and never repeat paid work. `usage.view` optionally supplies
query-safe app totals to the run tree; without it usage is null.

## Budget

`check(ctx, { subject, runId })` runs before model slices and local tool effects.
A denial ends the turn with `BUDGET_EXCEEDED` in activity. Slice admission posts a passive note from
`budget`, under the same `notesPending` cap as every other note. If that cap
is full the notice is omitted, but the typed denial still stops the turn.
The cap counts observed estimates and known spend, with no reservations.
Already-started work and delayed reconciliations can overshoot. There is no
resumable budget pause; the app may authorize a fresh run.

## Telemetry

`integration(facts)` returns an AI SDK integration and receives the turn facts
plus `turnKey`, a hash of the slice identity. `flush(facts, signal)` gets the
same identity, so an adapter can keep one buffer per turn. It runs in
`finally`, fails open and is bounded to three seconds.

## Sandbox

Sandbox tools need both a `sandbox` slot and the agent option `sandbox: true`.
Connect the module's trusted `onComplete` mutation to
`runtime.sandboxComplete(ctx, event)`: it authorizes the background `sandbox`
operation against the stored owner and posts a bounded passive note from
`sandbox`. Any managed thread may report a completion; the event names the
subject, thread, run and job, with a `state` of `done`, `failed` or `unknown`.

## Files

`open` and `send` accept `files?: string[]`: at most 8 native `storeFile` ids.
Attest the subject with `runtime.registerFile(mutationCtx, { agent, fileId,
subject })` in the trusted upload path. Admission rejects unregistered and
foreign files. A total above `limits.attachmentBytes` — 8 MiB by default, 16
MiB at the hard maximum — is rejected with `{ status: "rejected", code:
"ATTACHMENT_LIMIT" }`. Files reach the model as native parts.
`runtime.fileAttached(ctx, { subject, threadId, fileId })` answers the exact
attachment question for host tools.

## Structured tasks

`defineTask({ name, input, output, prompt, instructions?, model?, repair? })`
declares a schema-checked task; `instructions` (string or `(input) => string`)
is sent as the system message while `prompt` is the user message, bounded like
the prompt and reused unchanged by the repair re-ask. `runTask(hc, task, input)` inside a managed hook inherits
the component, attribution, usage and fence; `runtime.runTask(ctx, task,
input, { key, attribution })` supplies them explicitly. Outcomes are `{ status:
"done", value }`, `{ status: "failed", code }`, `{ status: "running" }`,
`{ status: "unknown" }` or a typed denial; one repair
re-ask is allowed, results fit 64 KiB, and an expired lease stays `unknown`.
