One `Agent` type represents roots and children. A child is an agent listed in
another agent's `subagents`. Registration allows two edges from each root;
`limits.maxDepth: 1` lowers that, and cycles or deeper graphs fail at
registration.

Parents receive `agevex_delegate` with `{ agent, task, group?, wait? }` and
`agevex_message_child` with `{ runId, text }`. Children receive
`agevex_ask_parent` with `{ question }` and
[`agevex_message_parent`](/docs/concepts/message-parent) with `{ text }`.

## Groups

`wait` defaults to `"each"`: each settled result reaches the parent
immediately. With `wait: "all"`, the group's final results wake its parent once, after the
launching slice ends and every member settles, failures included. Membership
seals when that slice ends, so a later launch into the same group returns
`GROUP_CLOSED`. A group holds at most `activeChildrenPerRoot` members: 5 by
default, 15 at the hard maximum. Names are at most 200 characters, and
omitting the name selects the unnamed group. Mixing `"each"` and `"all"`
members in one group returns `GROUP_CONFLICT`.

## Delivery rules

- **R1** The inbox holds ready work in FIFO order. A claim coalesces
  consecutive head rows and never crosses another run's turn.
- **R2** `agevex_ask_parent` is denied with `ASK_WITH_CHILDREN` while any
  descendant of the asking child is still non-terminal.
- **R3** A run settles only when its last turn ended, no descendant is running
  and its inbox is empty. Earlier final text does not finish a run while
  descendants still run.

A delivered result is the child's verified final text. A tool-only or empty
completion is a failed run, never a result.

## Questions and follow-ups

One open question pauses the child as `asking`, and its verified question wakes
the parent immediately, even inside a waiting group. The parent answers with
`agevex_message_child`. Each child accepts 4 follow-ups, 8 at the hard maximum.
Questions and follow-ups spend the run's hops and use `limits.taskLength`: 4,000
UTF-16 units by default, 16,000 at the hard maximum.

## Non-blocking progress

`agevex_message_parent({ text })` sends a short message to the immediate
persisted parent and lets the child keep working. A sleeping parent wakes at
its next safe turn, even while a wait-all group still has running members.
A running parent finishes its current tools/results first; progress never
bypasses an unresolved approval or deferred call. Woken turns record normal usage.

Accepted notes enter the parent's FIFO before that child's final delivery.
Consecutive notes and results may share a turn. Repeating the same tool-call
identity and input replays the original message id without saving or waking
again; a changed payload returns `KEY_CONFLICT`.

Text fits 2 KiB encoded, with at least 5 seconds between accepted notes and
4 accepted notes per child by default (`parentNotesPerChild`, maximum 8).
Each fresh note consumes one hop and one ready queue slot. Over-limit calls
return typed denials before saving. Finished or cancelled children cannot post;
notes committed before cancellation remain in history. There is no automatic
acknowledgement. The host's `runtime.note` remains passive and never wakes.

## Budgets

A user prompt starts one run. Launches, delivered results, notes, questions,
answers and follow-ups share 12 launches and 24 hops, with hard maxima of 50
and 100. Each launch reserves its result's hop; each question reserves its
answer hop. Notes, questions and follow-ups cannot spend those reserved hops.
Final results and joined groups always enter the ready queue, even above
`queueLength`. The queue limit applies to messages: user sends, parent notes,
questions and child follow-ups are refused at capacity (`QUEUE_FULL` for user
sends, `QUEUE_LIMIT` for component enqueues). Answers and approval continuations
retain their control allowance. Messages are refused until the queue drains
below its limit. Launch admission bounds outstanding result work per assignment
across user requests at `runLaunches`: pending deliveries, unreleased join members
and queued result rows. A joined row replaces its members; claim frees capacity.
Reaching this separate bound returns `RUN_BUDGET`. A root admits at most 5 active
descendants, 15 at the hard maximum. Only the recorded parent can send a child
follow-ups or answer its questions.

## Reading the tree

`runTree({ threadId })` is owner-authorized and root-only. It returns the
current request's descendants with agent, status, depth, group, parent
assignment, native child thread and timings. `delegations({ threadId,
paginationOpts })` returns the root thread's delegation history across requests,
newest-first, at most 50 runs per page. Every run
carries `side: boolean`, marking a side review as distinct from a child.

## Per-agent model overrides

`open` and `send` accept `models: { Main: "model-id" }`. Register
`modelAllowlist` and `models: id => provider.chat(id)`; only reachable agent
names and allowed ids are accepted. Each accepted prompt starts a run with an
immutable model snapshot that every descendant and result turn shares. A later
send updates the next run only: omitting `models` inherits the last accepted
thread policy, and `{}` restores the Agent defaults. A map holds at most 8
entries and 512 Convex-encoded bytes, with ids of at most 200 characters.

The model calls `agevex_delegate` with `agent: "Builder"`, a task,
`group: "draft"` and `wait: "all"`. This is a managed model tool, not a
JavaScript function exported to the host.
