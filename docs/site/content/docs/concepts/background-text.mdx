---
title: Background titles
description: Native thread titles with receipt-backed dispatch.
status: Available
---

Titles generate once after the first accepted native user message. Configure
`title: { model, prompt, maxOutputTokens }` or disable with `title: false`.
The default model is the root model, including accepted model overrides.
Export `textTask` from `runtime.internalFunctions()` and supply `refs.textTask`.
Generated-reference cycles may use `RegisteredAction<"internal", TextTaskArgs, null>`.

`title({ threadId })` reads `{ text: string | null }` from Agent.
`rename({ threadId, text })` writes the native title; identical writes replay.
The returned `messageId` identifies the thread; renaming creates no message.
The native title check and generated update share one transaction, so app/user
titles always win. Public reads and writes authorize the persisted root owner.

Workers use child/background capacity, recheck `authorizeExecution` with
`purpose: "title"` and the budget hook, then read the first prompt by exact id.
Input fits 48 KiB. Output defaults to 128 tokens, configurable up to 4,096;
titles fit 120 characters and 512 encoded bytes. Calls have a 30-second timeout,
no tools, no repairs and no automatic paid retries.

The existing receipt ledger holds temporary run/first-message identities and
dispatch status, never generated text. The paid lease starts at dispatch.
Crashes become unknown and never buy a second call. Titles survive cancellation
because they describe the first accepted message. Usage callbacks receive the
triggering run and provider response id; observation failures mark usage partial.
Apps own their pricing and budget policy.
