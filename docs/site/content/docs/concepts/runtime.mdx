## Available: current runtime basics

Today, Workpool dispatches one action per turn, with a 120-second watchdog.
Uncertain outcomes enter `recovery_required` and are not retried. Delegation is
depth 1; result turns cannot delegate, and there is no cancel or durable waiting.
The native Agent component keeps the transcript and streaming.

## Planned: Workflow-backed turns

A long-lived loop workflow manages each thread. It runs turn workflows and sleeps
on `awaitEvent('ping')` when the inbox is empty. Inbox rows are the source of
truth; a ping is only a doorbell.

```text title="Planned workflow execution"
open/send → inbox row (durable) → ping
loop workflow (one per managed thread)
  └─ turn workflow
       take next inbox row
       repeat slice ≤ maxSlices:
         agentStep action (one model step, maxRetries 0, retry false)
         tools run inside the step; delegation/sandbox/extract enqueue work
         between slices: take steering posts, check budget, check cancel
       if waiting on children/jobs → awaitEvent, then continue
       report to parent (if child) → finish
```

Each slice performs one model step. Paid actions use `maxRetries: 0` and
`retry: false`; recovery is explicit. The workflow can resume and record a typed
failure without automatically repeating paid generation.

Only IDs cross steps. Transcripts, file bodies and tool outputs stay outside
workflow arguments: the journal is bounded to 8 MiB and a step value to 800 KiB.
Step order is versioned and protected by journal replay checks.

Cancellation cannot stop an action directly. Actions poll a cancel flag about
every second, abort through an `AbortController`, and fence writes with
`(executionId, cancellationEpoch)`.

## Registration shape (planned)

```ts title="Planned runtime registration"
const runtime = registerAgent(components.sdk, {
  agents: [main],
  refs: { runTurn: () => internal.agents.runTurn, coordinate: () => internal.agents.coordinate },
  authorize,                // public reads/writes + background ops (unchanged contract)
  authorizeExecution,       // before every generation (unchanged)
  limits?: Partial<Limits>, // §3.3 bounds
  observe?: ObserveAgentEvent,   // PR #2
  usage?: UsageHooks,            // §6
  telemetry?: TelemetryOptions,  // §7
})
export const { open, send, cancel, messages, activity, delegations } =
  runtime.authorizedEndpoints()
```

The draft renames `registerAgevex` to `registerAgent`. Public operations and
background operations still require host authorization; execution policy is
checked before every generation.

## State ownership

The draft evolves assignments into threads and pending rows into a FIFO inbox.
It extends receipts and child runs, and adds one core table, `runs`, for a user
request’s launch/hop counters and budget. It does not copy Workflow or Workpool
state. The Agent component still owns threads, messages and streaming.

Tools receive trusted facts, rather than an SDK permission system:

```ts title="Planned tool context"
type ToolContext = {
  ctx: ActionCtx; // the normal Convex action ctx
  subject: string; // whose request this is (the thread owner)
  threadId: string; // the thread this call runs in (root or child)
  runId: string; // the user request it belongs to (grouping, costs)
  toolCallId: string; // unique per call; a ready-made idempotency key
  signal: AbortSignal; // fires on cancel or deadline; pass to fetch/providers
};
```

The host enforces tool permissions. See [delegation](/docs/concepts/delegation),
[idempotency](/docs/concepts/idempotency) and [limits](/docs/concepts/limits).
