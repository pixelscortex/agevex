## Register once

`registerAgent(component, registration)` returns `authorizedEndpoints()`,
`internalFunctions()`, `runTask`, `registerFile`, `fileAttached`, `note`
and `sandboxComplete`. See the complete [registration](/docs/getting-started).

Export `runTurn` and `coordinate` as internal host functions. Only roots go in
`registration.agents`; reachable children belong in each Agent's `subagents`.
Direct native Agent calls remain unmanaged.

## Execute bounded slices

Each managed thread has a loop Workflow. It reserves FIFO inbox work and invokes
a turn Workflow, which dispatches one host action per model slice. Root and child
lanes default to parallelism 2 and 4. Only ids and small control values cross
Workflow steps. Journals rotate before their 8 MiB ceiling.

A slice rechecks authorization and budget, runs hooks, executes one native model
step and records exact saved ids. Tool calls can admit the next slice. The default
is 16 slices per turn, at most 64. Model retries and paid action retries are
disabled. Per-agent model and tool deadlines bound waiting; the watchdog is
derived from their validated combined action budget.
An uncertain outcome enters `recovery_required`; it never silently regenerates.

## Authorize at both boundaries

`authorize(ctx, scope)` returns `{ subject }` for public operations and
background delegation, delivery and sandbox completion. Background scopes carry
persisted, capability-checked facts; recheck them against current host policy.
Do not require an interactive identity on a background call or blindly echo its
subject.

`authorizeExecution(actionCtx, scope)` runs before every model generation,
including children and result turns. It returns void or throws. It receives
server-derived assignment, thread, run-origin and optional child facts.

## Public host endpoints

The following endpoints come from `runtime.authorizedEndpoints()`.
All require the host authorization policy. Optional arguments use `?`.

| Endpoint      | Arguments                                     | Result                                         |
| ------------- | --------------------------------------------- | ---------------------------------------------- |
| `open`        | `agent, prompt, requestKey, models?, files?`  | `Receipt` for a new root thread                |
| `send`        | `threadId, text, requestKey, models?, files?` | `Receipt` for an existing root                 |
| `respond`     | `threadId, approvalId, approved, reason?`     | `{ messageId, replayed }`                      |
| `answer`      | `threadId, toolCallId, text`                  | `{ messageId, replayed }`                      |
| `cancel`      | `threadId`                                    | `null`                                         |
| `messages`    | `threadId, paginationOpts`                    | Native message page with origin metadata       |
| `streams`     | `threadId, streamArgs`                        | Native stream synchronization result           |
| `activity`    | `threadId`                                    | `Activity` for a root                          |
| `runTree`     | `threadId`                                    | Current root request's bounded descendant tree |
| `delegations` | `threadId, paginationOpts`                    | Root history, newest first                     |

## Cancellation

Cancel fences the root and every live descendant in one bounded transaction.
Running actions poll cancellation about once a second. Their managed writes
check the execution id and cancellation epoch. Cancellation settles recorded
pending calls with native execution-denied results; it cannot retract an
external request already in flight. A fresh send can reopen a cancelled thread
once cleanup succeeds.

The component's execution read is
`components.agevex.turns.slices.execution`, a bounded projection for the host
runner. It is internal coordination data, not a public authorization surface.
See [architecture](/docs/concepts/architecture) for ownership and current paths.

## Per-agent run settings

Managed calls accept per-agent policy without changing shared native Agent options:

```ts
const reviewer = new Agent(native, {
  name: "Reviewer",
  languageModel: model,
  run: {
    mode: "generate",
    maxOutputTokens: 2048,
    modelTimeoutMs: 45_000,
    toolTimeoutMs: 15_000,
    stepsPerTurn: 6,
  },
});
```

| Agent.run setting | Default  | Hard bound                                 |
| ----------------- | -------- | ------------------------------------------ |
| `mode`            | `stream` | `stream` or `generate`                     |
| `maxOutputTokens` | 4,096    | Integer 1–32,768 per model step            |
| `modelTimeoutMs`  | 90,000   | Integer 1,000–300,000 per provider call    |
| `toolTimeoutMs`   | 90,000   | Integer 1,000–300,000 per local invocation |
| `stepsPerTurn`    | 16       | Integer 1–64 model steps per logical turn  |

`stream` uses native `streamText` with deltas; `generate` uses native
`generateText` without deltas. Both save native messages, usage, tool calls
and approval pauses. Each model step remains one non-retried action/slice;
finish, approval, question or delegation can end the turn earlier. Provider
output limits may be smaller. Direct native calls remain unmanaged.

Registration validates individual bounds and the combined action budget:
`modelTimeoutMs + 16 * toolTimeoutMs + 30_000 <= 1_800_000`. The watchdog uses
this same budget, starting at claim. At most sixteen tool calls are accepted per
slice; local tools execute serially. Model time excludes tools. Tool timeouts
abort the slice, signal cooperative tools and stop waiting for uncooperative
ones. External effects can still finish; late managed writes are fenced and
unknown paid outcomes are never automatically retried.

Each accepted request snapshots the resolved per-agent map on its root `runs`
row. Children and result turns read that same run id, so registration changes
apply only to newly accepted requests. The map fits 15 KiB, reserving 1 KiB for
model overrides, counters and native row metadata within the 16 KiB run envelope.
The existing `limits.slicesPerTurn` supplies the default when `run.stepsPerTurn`
is omitted; an explicit host slice override also caps the Workflow turn.

## Shared lane capacity

`registerAgent(component, { ...registration, limits: { rootLane: 2, childLane: 3 } })`
uses the existing two Workflow/Workpool lanes. The defaults are 2 roots and 4
children, with positive integer maxima of 4 each (8 total platform slots).
One mounted component owns one shared pair of pools. Registrations on that
mount must agree: acceptance refuses conflicting capacity with
`LANE_CONFIGURATION_CONFLICT`. Sleeping workflows use no action slots;
per-agent run settings do not create additional pools.
