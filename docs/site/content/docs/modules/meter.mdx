Meter records provider costs and gates the next slice on known spend. Use it for
per-run budgets, cost breakdowns or billing sinks. Its Convex component owns
charges, operation receipts and a durable sink outbox. Host functions own pricing,
authorization, provider evidence and sink credentials.

Saved steps and app-reported tool usage appear during work. Inline provider cost
is authoritative; otherwise a configured token estimate contributes to the same
run budget. Later billing evidence replaces that charge's contribution.

## Wire it into agevex

Install the [built package and peers](/docs/getting-started). Meter needs no
additional host package. Mount it explicitly as `meter`:

```ts title="convex/convex.config.ts"
import { defineApp } from "convex/server";
import agent from "@convex-dev/agent/convex.config";
import agevex from "agevex/convex.config";
import meter from "agevex/meter/convex.config";

const app = defineApp();
app.use(agent, { name: "agent" });
app.use(agevex, { name: "agevex" });
app.use(meter, { name: "meter" });
export default app;
```

Define the host workers. Inline OpenRouter evidence requires provider usage cost
metadata; request `usage: { include: true }` on OpenRouter model calls.

```ts title="convex/billing.ts"
import { defineMeter, openRouterProvider, polarSink, tokenEstimate } from "agevex/meter";
import { components, internal } from "./_generated/api.js";

export const meter = defineMeter(components.meter, {
  providers: {
    openrouter: openRouterProvider({
      apiKey: () => process.env.OPENROUTER_API_KEY!,
      // Example rates only: replace with your model's current pricing.
      estimate: tokenEstimate({ inputUsdPerMillion: 1, outputUsdPerMillion: 2 }),
    }),
  },
  // The getter runs when a delivery is made, never at module load.
  sinks: [polarSink({ meter: "ai_usage", accessToken: () => process.env.POLAR_ACCESS_TOKEN! })],
  workers: {
    lookup: internal.billing.meterLookup,
    deliver: internal.billing.meterDeliver,
  },
  budgets: () => ({ maxUsd: 5 }),
});
export const { meterLookup, meterDeliver } = meter.internalFunctions();
```

Credential options (`polarSink.accessToken`, `openRouterProvider.apiKey`) take a
string or a getter returning a string or promise. A getter is called at each
delivery or lookup, never at construction, so hosts that forbid reading env at
module load can pass `() => process.env.X!`. An empty or oversized (over 4 KiB)
`polarSink` token fails that delivery with `POLAR_TOKEN_REQUIRED`.

Replace `convex/agents.ts` from [getting started](/docs/getting-started). Keep
its `agentConfig.ts`, which supplies the agents, policies and internal refs.

```ts title="convex/agents.ts"
import { registerAgent } from "agevex";
import { components } from "./_generated/api.js";
import { registration } from "./agentConfig.js";
import { meter } from "./billing.js";

export const runtime = registerAgent(components.agevex, {
  ...registration,
  usage: meter.usageSlot(),
  budget: meter.budgetSlot(),
});
export const { runTurn, coordinate, textTask } = runtime.internalFunctions();
export const {
  open,
  send,
  cancel,
  respond,
  answer,
  messages,
  streams,
  activity,
  runTree,
  delegations,
} = runtime.authorizedEndpoints();
```

Core derives attribution and replay-stable keys. `usageSlot` resolves exact
provider names, explicit mappings, then the longest registered dotted prefix.
For example, `openrouter.chat` resolves to `openrouter`. Unresolved providers
record unknown cost. Do not also attach `usageHandlerFor` to managed calls.

For several model prices, supply `Provider.estimate({ usage, model })` to select
the host's rate. Native Agent's saved `promptTokens` / `completionTokens`, AI SDK
usage and V4 token totals are supported by `tokenEstimate`. No rate is inferred.

## Reconciliation and live reads

Core preserves the provider response id in the same native save as usage. Charges
carry `purpose` (`agent`, `hook`, `tool`, `title`, `summary`) and an optional delegation
`nodeId`; ordinary model/tool calls set these from trusted runtime facts.
Each slice exit, including early child completion, asks the usage slot to sweep
pending request ids. Meter discovers them through its run index, four charges per
transaction. Its jobs only read billing evidence. They cannot regenerate an answer.

`openRouterProvider` reads OpenRouter's generation `total_cost` with a 30-second
timeout and 16 KiB response ceiling. Other providers implement `Provider.lookup`.
Missing/failed responses retain the estimate and retry up to eight times within
one hour by default (maximum one day). After expiry the estimate remains on the
row as estimated, so lookup outages do not independently deny budget admission. The charge's `reconciliation`
field exposes pending, running, complete, unavailable or exhausted evidence.
An authoritative inline cost, including zero, needs no lookup.

Standalone code can save `record(provider, { key, usage, requestId })` and call
`meter.reconcile(ctx, { subject, runId })` afterwards. Repeat that bounded sweep
as a backstop; it updates existing charges and schedules no duplicate lookups.
`charge.attach` remains available for request ids learned later.

Compose an authorized reactive host query with
`meter.usageView(ctx, { subject, runId, nodeIds, partial? })`. Supply known exclusive
node ids (at most 59; `null` denotes root). It returns root-run totals and node
totals with input/output tokens, `estimatedUsd`, `settledUsd`, unknown count and
reporting coverage. No charge or transcript scan occurs. Missing token evidence
is `null`; real zero is retained. Unknown cost or missing model tokens reports
partial coverage. Core stores a sticky `runs.usagePartial` after an observation
failure; host projections read `turns.slices.usageReporting` and pass it as
`partial`. Without a usage/view adapter, no usage view is exposed.

Usage recording, attach and settlement failures never repeat paid work or replace
a successful tool result. Evidence and invoice totals are best effort.

## Charge and budget semantics

`scope(ctx, attribution)` serves standalone host operations. Supply stable
creation keys and a distinct stable operation key for each attach/correct/settle.
Creation-key conflicts throw `KEY_CONFLICT`. Operation-key replays return their
original snapshots; use `get()` for current state. After 32 operation keys,
new operations fail with `OPERATION_CAPACITY`; retained keys still replay.

Providers can combine `inline`, per-unit `profiles`, `credits` conversion
and read-only `lookup`, with optional token `estimate`. Lookup never repeats a paid provider call. Unknown
cost denies the budget check even without a configured cap. Estimates count
against the cap; checks run before the next model call and local tool effect.
A denial stops with `BUDGET_EXCEEDED`. In-flight work and delayed provider costs
may overshoot. This is a snapshot cap with no credit reservation or resumable
pause; further spending needs a fresh authorized run.

Unknown charges with `purpose: "title" | "summary"` are the exception to the
fail-closed rule: the run-scoped gate ignores them, so a failed background call
never stops the run that triggered it. They stay recorded, billed and counted in
`unknown`, and their estimated or settled amounts still count toward the run's
spend; `blockingUnknown` reports what the gate denies on. Turn, hook and tool
unknowns, and subject-wide checks without a `runId`, still deny.

Amounts above $90 remain `unknown / OVER_CAP`: aggregates count at most $90
for that charge, while sinks retain its full known amount. Other unknown reasons
include missing/invalid evidence, unregistered providers/profiles and root-thread
capacity. Authoritative settlement can resolve an unknown charge. Settlement is
final; later amount changes are ignored.

`authorize` guards standalone operations. Core slots trust server-derived
attribution and skip that callback. Public wrappers must check ownership.
`prune` has no authorization callback; put it behind a host admin check.
Pruning makes a removed key available again, so retain keys beyond your replay
window. Model/provider breakdowns are opt-in and do not backfill old charges.

## Limits

| Bound                                     | Default / ceiling                                   |
| ----------------------------------------- | --------------------------------------------------- |
| Providers / profiles per provider / sinks | 16 / 32 / 4                                         |
| Charges per root thread                   | 100,000; lower with `limits.maxThreadCharges`       |
| Distinct operation keys per charge        | 32                                                  |
| Group page / breakdown day window         | 4 / 7; may be lowered                               |
| Lookup/delivery attempts                  | 8; may be lowered                                   |
| Lookup horizon                            | 1 hour default, 1 day maximum                       |
| Sink batch / acknowledgement batch        | 100 / 16                                            |
| Prune batch                               | 100 default, 500 maximum, also transaction-budgeted |
| Minimum prune age                         | 7 days default; host may lower it                   |
| Labels / keys                             | 128 / 256 UTF-8 bytes                               |

Sinks deliver known amounts independently of the gate. Use stable sink event
keys for downstream dedupe. Custom sinks receive `deliver(batch, ctx)`, where
`ctx` is the delivery worker's host action context and can call host internal
mutations. Existing one-argument callbacks still work.

Set `estimates: true` on an individual sink to deliver initial known estimates
as usage arrives. The option is frozen per charge at creation, without backfill;
default sinks still wait for correction or authoritative cost. `webhookSink`
accepts the same option; `polarSink` does not, because Polar bills every ingested
event and only ever receives final amounts.

Each event freezes `status` (`estimate`, `settled`, `corrected`, `unknown`) and
`source` (`estimate`, `inline`, `settlement`, `lookup`) when enqueued. Corrections
use source `estimate`. An estimate-to-settled transition at the same amount emits
a new monotonic revision with `nanos: 0`, sent only to sinks with
`estimates: true`. `totalNanos` remains the absolute cost; group by charge `key`
to replace totals using newer revisions. The first event's
`externalId` is its charge key; later revisions use `key:delta:revision`.
Retries preserve the same externalId/revision, including its frozen
classification. An over-cap correction after a delivered estimate makes the
charge `unknown` and sends no revision until settlement. Write each batch in one
idempotent host mutation keyed by `externalId`. Pending events remain unchanged
until acknowledged, then a new revision catches up to the latest charge state.

Explicit `retrySinks` resets failed delivery;
unknown paid work is never retried. See the
[module README](https://github.com/pixelscortex/agevex/blob/HEAD/src/modules/meter/README.md)
and [API notes](https://github.com/pixelscortex/agevex/blob/HEAD/src/modules/meter/API.md).
