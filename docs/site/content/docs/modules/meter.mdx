`sdk/meter` records what any call cost, answers what a thread, run or user
cost, gates the next slice of work, and forwards settled charges to whatever
bills the customer. It knows nothing about plans or prices beyond what the host
tells it.

## One lifecycle for every provider

Providers report cost inline (OpenRouter), later by request id (Fal), in
credits (Firecrawl, Daytona) or never. Every charge follows one path, and
"not known yet" is never counted as zero:

```text
estimate ──▶ settled     provider reported the real cost
   │    └──▶ corrected   quantity or tier fixed by the host
   └──────▶ unknown      lookup window expired; stays visible
```

## Profiles

Assumptions are written down once, per provider:

```ts title="Planned meter config"
const meter = defineMeter(components.meter, {
  providers: {
    openrouter: inline(),                                  // cost arrives with the response
    fal: {
      profiles: { "image:high": { unit: "image", usd: 1.0 } },
      lookup: (ctx, requestId) => falCost(requestId),      // optional: real cost later
      lookupFor: "1h",                                     // then the charge becomes unknown
    },
    firecrawl: { credits: { usdPerCredit: 0.001 } },
  },
  sinks: [polarSink({ meter: "ai_usage" })],               // optional
  budgets: (scope) => ({ maxUsd: 5 }),                     // optional
})
```

## Recording

Model calls are metered by core, once per saved step. Inside a tool,
`tc.meter` is already attributed to the thread, run, agent and subject:

```ts title="Planned tool usage"
const charge = await tc.meter.estimate("fal", { profile: "image:high", quantity: 6 })
const res = await fal.run(...)
await charge.attach({ requestId: res.requestId })   // looked up later
await charge.correct({ quantity: 5 })               // or fix it yourself
await charge.settle({ usd: 4.87 })                  // or settle it directly
```

Outside tools, `meter.scope(ctx, { subject, threadId? })` returns the same
object. Without a configured meter, `tc.meter` is a no-op.

## Asking

```ts title="Planned reads"
await meter.threadCost(ctx, { threadId })   // root + children
// → { usd: { settled, estimated }, unknown, byAgent, byModel, byProvider }
await meter.breakdown(ctx, { subject, from, to, by: "day" | "agent" | "model" | "provider" })
await meter.check(ctx, { subject, runId })  // budget gate, counts estimates
```

## Built on

- Totals live in `@convex-dev/aggregate`, so cost reads never scan.
- One owned `charges` table holds status, attribution and provider request ids.
- Lookups and sink delivery run on Workpool with retries. A failing sink never
  blocks agent work.
- `polarSink` ingests settled charges as Polar meter events. The Polar
  component still owns subscriptions and webhooks.
- Calls routed through the Convex AI Gateway reuse `@convex-dev/ai-budget`
  pricing.
