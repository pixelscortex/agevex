Tools are editable source from the [registry](/docs/registry). Install only
what you need into an existing agevex host; no extra Convex component is mounted.
Set `"tsx": true` in the host's `components.json` before installing.

| Item | Contract and state |
| --- | --- |
| [Todo](/docs/tools/todo) | `todo_read` / `todo_write`: replace or read up to 100 items and 32 KiB per list. Host table `agevexTodos`, scoped by owner and thread. |
| [Goals](/docs/tools/goals) | `goal_set` / `goal_check`: set or read one goal, up to 4000 characters. Host table `agevexGoals`: one row per owner and thread, owned by the run that set it. |
| [Ask the user](/docs/tools/ask-user) | `ask_user`: a deferred question up to 2000 characters, answered with free text through core `answer`. No item table. |
| [Continue budget](/docs/tools/continue-budget) | `continue_budget`: native approval with a reason up to 2000 characters, plus `resumeAfterBudgetStop`, an atomic one-mutation resume for runs stopped with `BUDGET_EXCEEDED`. Host table `agevexBudgetConsents` records the owner's consent; consent does not change budget policy. |

Start the docs site from `docs/site` with `bun run dev`, or replace the origin:

```sh title="Terminal"
bunx shadcn add http://localhost:3000/r/todo.json
bunx shadcn add http://localhost:3000/r/goals.json
bunx shadcn add http://localhost:3000/r/ask-user.json
bunx shadcn add http://localhost:3000/r/continue-budget.json
```

Merge the todo, goal and consent table snippets into your existing host schema. Each
item's guide shows its factory and registration. Todo, goals and
continue-budget use core `defineOnceTool` for trusted `ToolContext` facts,
cancellation fences and idempotent results; `ask_user` is a deferred tool with no
`execute`. Ownership is never model input; the host keeps its
`authorize` and `authorizeExecution` policies and owns state retention.

Answer `ask_user` with core `answer({ threadId, toolCallId, text })` and
`continue_budget` approvals with core `respond({ threadId, approvalId, approved })`
so the waiting turn wakes; saving a native result or response directly does not.
Pending-call state lives in core and the native Agent.
