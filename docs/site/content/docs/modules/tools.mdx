Tools are editable source from the [registry](/docs/registry). Install only
what you need into an existing agevex host; no extra Convex component is mounted.
Set `"tsx": true` in the host's `components.json` before installing.

| Item | Contract and state |
| --- | --- |
| [Todo](/docs/tools/todo) | `todo_read` / `todo_write`: replace or read up to 100 items and 32 KiB per list. Host table `agevexTodos`, scoped by owner and thread. |
| [Goals](/docs/tools/goals) | `goal_set` / `goal_check`: set or read one goal, up to 4000 characters. Host table `agevexGoals`, scoped by owner, thread and run. |
| [Ask the user](/docs/tools/ask-user) | `ask_user`: a yes/no question up to 2000 characters using native approval. No item table. Free-text answers are coming through a core endpoint. |
| [Continue budget](/docs/tools/continue-budget) | `continue_budget`: native approval with a reason up to 2000 characters. No item table; consent does not change budget policy. |

Start the docs site from `docs/site` with `bun run dev`, or replace the origin:

```sh title="Terminal"
bunx shadcn add http://localhost:3000/r/todo.json
bunx shadcn add http://localhost:3000/r/goals.json
bunx shadcn add http://localhost:3000/r/ask-user.json
bunx shadcn add http://localhost:3000/r/continue-budget.json
```

Merge the todo and goal table snippets into your existing host schema. Each
item's guide shows its factory and registration. All tools use core
`defineOnceTool` for trusted `ToolContext` facts, cancellation fences and
idempotent results. Ownership is never model input; the host keeps its
`authorize` and `authorizeExecution` policies and owns state retention.

Answer approvals through core
`respond({ threadId, approvalId, approved, reason? })` so the waiting turn
wakes. Native approval parts and core receipts hold approval state; saving
a native response directly does not wake core.
