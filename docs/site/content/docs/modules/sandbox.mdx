## Setup

Mount alongside Agent and agevex; declare the Daytona key in the app environment.

```ts title="convex/convex.config.ts"
import { defineApp } from "convex/server";
import { v } from "convex/values";
import agent from "@convex-dev/agent/convex.config";
import agevex from "agevex/convex.config";
import sandbox from "agevex/sandbox/convex.config";
import daytona from "@daytona/convex/convex.config";

const app = defineApp({ env: { DAYTONA_API_KEY: v.string() } });
app.use(agent);
app.use(agevex);
app.use(sandbox);
app.use(daytona, { env: { DAYTONA_API_KEY: app.env.DAYTONA_API_KEY } });
export default app;
```

Register host internal functions. `hostSandboxPolicy` below is host-owned.

```ts title="convex/sandboxes.ts"
import { defineSandbox, daytona, type PollArgs, type SettleArgs } from "agevex/sandbox";
import type { RegisteredAction, RegisteredMutation } from "convex/server";
import { components, internal } from "./_generated/api";
import { hostSandboxPolicy } from "./sandboxPolicy";

export const sandbox = defineSandbox({
  component: components.sandbox,
  provider: daytona(components.daytona, { autoStopInterval: 0 }),
  scope: "thread",
  agent: components.agent,
  authorize: hostSandboxPolicy,
  refs: {
    poll: () => internal.sandboxes.poll,
    settle: () => internal.sandboxes.settle,
    cleanup: () => internal.sandboxes.cleanup,
  },
});
const functions = sandbox.internalFunctions();
export const poll: RegisteredAction<"internal", PollArgs, null> = functions.poll;
export const settle: RegisteredMutation<"internal", SettleArgs, null> = functions.settle;
export const cleanup: RegisteredAction<"internal", Record<string, never>, null> = functions.cleanup;
export const tools = sandbox.tools(); // Add these to the host Agent's tools.
```

`authorize(ctx, request)` must recheck current host policy and return `{ subject }`.
Operations are `use`, `export`, `stop`, `delete`, `poll`, and `cleanup`; scheduled
calls have no end-user identity. Supplied subjects must match the policy result.
Expose host endpoints calling these helpers, never raw component references.
Pure reads require trusted `ToolContext` in AI SDK 7's `context` or a host-bound
`sandbox.tools(tc)` factory. Effects use core's `defineOnceTool` receipt binding.

## API

### Registration and scope

| Function | Signature and behavior |
| --- | --- |
| `defineSandbox` | `defineSandbox(options: SandboxOptions)` — validates registration and returns the helpers below. |
| `daytona` | `daytona(component, opts = {}): SandboxProvider` — wraps `@daytona/convex`; accepts its client options plus `snapshot`, `target`, `autoStopInterval`, and `autoArchiveInterval`. |
| `sandboxNodeExport` | `sandboxNodeExport(options: SandboxOptions)` — registers an internal export action in a host `"use node"` file. |
| `sandbox.tools` | `tools(context?: ToolContext)` — returns the five tools below. |
| `sandbox.scopeKey` | `scopeKey(facts: SandboxFacts): Promise<string>` — hashes scope, subject, and selected scope identity. |
| `sandbox.prepare` | `prepare(tc: ToolContext)` — authorizes, reserves, saves the sandbox ID, and resumes; returns `{ sandboxId, scopeKey, claim }`. |
| `sandbox.readFile` | `readFile(tc: ToolContext, input: { path: string })` — returns `{ content }`, the bounded text tail. |
| `sandbox.list` | `list(tc: ToolContext, input: { path: string })` — returns `{ entries: FileEntry[] }`. |
| `sandbox.internalFunctions` | `internalFunctions()` — returns internal `poll({ jobId })` action, `settle(args: SettleArgs)` mutation, and `cleanup({})` action. |
| `sandbox.job` | `job(ctx: SandboxContext, input: PollArgs)` — authorized bounded snapshot or `null`, including unknown outcomes. |
| `sandbox.export` | `export(ctx: SandboxContext, input: SandboxExportArgs): Promise<SandboxExportResult>` — exports an existing binding's file through native Agent `storeFile`. |
| `sandbox.stop` | `stop(tc: ToolContext): Promise<void>` — stops the VM, preserving identity and files for next use. |
| `sandbox.delete` | `delete(tc: ToolContext): Promise<void>` — explicitly requests deletion; active jobs protect the filesystem. |
| `sandbox.cleanup` | `cleanup(ctx: SandboxContext)` — authorizes and schedules a finite TTL sweep; requires `refs`. |

`SandboxFacts` contains trusted `subject`, `threadId`, and `runId`.
`scope: "thread" | "run" | "subject"` chooses sharing; every key includes the
subject. Models never supply sandbox IDs. `sandbox.limits` contains resolved bounds.
Optional `usage.record(ctx, event)` receives best-effort, estimate-only metadata;
observer failures do not change effects.

### Five tools

| Tool input | Result |
| --- | --- |
| `sandbox_exec({ command })` | `{ status: "done", exitCode, stdout, stderr, truncated }` or `{ status: "unknown" }`; stdout/stderr share a tail allowance, preferring stderr. |
| `sandbox_read_file({ path })` | `{ content }` — bounded text tail, outside the receipts ledger. |
| `sandbox_write_file({ path, content })` | `{ status: "done" }` or `{ status: "unknown" }`. |
| `sandbox_list({ path })` | `{ entries }` — bounded `{ name, isDir, size? }` entries, outside the ledger. |
| `sandbox_run_background({ command })` | `{ status: "running" \| "unknown", jobId }` — requires `refs`; does not hold an action open until completion. |

### Provider contract

Implement `SandboxProvider` to supply another adapter. Here `ctx` is
`SandboxContext`, IDs/paths/commands are strings, `job` is `BackgroundJob`,
and `location` is `BackgroundLocation` (sandbox ID and private directory).
Each method returns a Promise of the listed result.

| Method signature | Result / contract |
| --- | --- |
| `create(ctx, { scopeKey })` | `{ sandboxId }` before waiting for readiness. |
| `resume(ctx, sandboxId)` | `void`; ready is a no-op; stopped, archived, and recoverable error states preserve files. |
| `stop(ctx, sandboxId)`, `delete(ctx, sandboxId)` | `void`; VM lifecycle. |
| `exec(ctx, sandboxId, cmd, { timeoutS, signal })` | `{ exitCode, stdout, stderr }`; no command retries. |
| `startBackground(ctx, sandboxId, cmd, job?)` | `BackgroundJob`; honor supplied persisted identity/location even if launch throws; no launch retries. |
| `poll(ctx, jobId, location)` | `JobOutcome`: `state: "running" \| "done" \| "failed" \| "unknown"`, optional `exitCode`, `logTail`, `code`. |
| `cancelBackground(ctx, jobId, location)` | `void`; bounded original-group cleanup, verifying ownership before fallback signaling. |
| `readFile(ctx, sandboxId, path, { maxBytes })` | `string`; enforce byte bound before returning across Convex. |
| `writeFile(ctx, sandboxId, path, content: string)` | `void`. |
| `listFiles(ctx, sandboxId, path, { limit })` | `FileEntry[]`; enforce count before returning across Convex. |
| `upload(ctx, sandboxId, path, content: Uint8Array)` | `void`; Daytona accepts at most 512 KiB per call. |
| `download(ctx, sandboxId, path, { maxBytes, offset?, totalSizeLimit? })` | `Uint8Array`; bounded window, short window means EOF; reject total-size overflow and keep bytes out of component args/rows. |

Daytona snapshots must contain `python3`.
Auto-stop defaults to 15 minutes, auto-archive to 10; both accept 0–525,600 minutes.
Use `autoStopInterval: 0` for jobs that must outlive the idle interval.
Provider auto-delete is disabled with `autoDeleteInterval: -1`.

### Background completion

Optional `onComplete(ctx, event)` commits atomically with terminal state and receives
`{ type: "sandbox.job.completed", jobId, providerJobId?, scopeKey, subject,
threadId, runId, state: "done" | "failed" | "unknown", exitCode?, logTail?, code? }`.
Use transactional writes in the callback. Status and callback failures retry until
the deadline, then leave an unknown snapshot readable through `sandbox.job(ctx, { jobId })`.
Deadline expiry records `SANDBOX_JOB_DEADLINE`; revoked authority records unknown without provider access or a callback.
Completion and deadline cleanup terminate descendants in the original process group;
processes that detach with `setsid` or daemonize require stopping or deleting the sandbox.

### Provider notes

Daytona uses bounded execs and a Python supervisor outside the job's process group,
retaining its leader through SIGTERM/SIGKILL. Identity and exit status publish by
atomic rename. Cancellation uses a control file; fallback signaling checks every
group member's `AGEVEX_JOB` marker in `/proc`, leaving unverified ownership unknown.
These markers do not protect against hostile code inside the VM.

### File exports

`sandbox.export(ctx, { threadId, path })` returns
`{ fileId, storageId, bytes, sha256 }`. It requires `agent`, never creates a
missing binding, and retains files on read failure. Run scope additionally
requires `resolveThread(ctx, threadId): Promise<SandboxFacts>` from host-owned
state; subject and thread must match authorization.

Default-runtime exports have an **8 MiB hard maximum**. For larger files,
register this action and pass its reference as `nodeExport` to `defineSandbox`:

```ts title="convex/sandboxExports.ts"
"use node";
import { sandboxNodeExport } from "agevex/sandbox";
import { sandboxOptions } from "./sandboxOptions";

export const exportFile = sandboxNodeExport(sandboxOptions);
```

Here `sandboxOptions` is host-owned shared `SandboxOptions` configuration;
set `nodeExport: internal.sandboxExports.exportFile` on the default registration.
Oversized exports route to the Node action, repeating authorization and trusted
scope resolution. `exportBytesNode` defaults to a **64 MiB hard maximum**.
Both bounds can be lowered. Without registration, overflow throws
`SANDBOX_EXPORT_TOO_LARGE` naming `sandboxNodeExport()`.

Exports hash incrementally in windows of at most 512 KiB, then store one Blob.
Daytona stages temporary windows for its non-recording file API; bytes never
enter execution rows, component arguments, or receipts. Interrupted transfers
create no storage object. Conservative whole-file allocations are 4× the limit:
32 MiB in the default 64 MiB runtime or 256 MiB in the 512 MiB Node runtime,
plus bounded transport windows and runtime overhead.

## Limits

Exported `LIMITS` and `HARD_LIMITS` define these `limits` overrides.
All require positive safe integers; `pollMinMs <= pollMaxMs`.

| Option | Default | Hard maximum |
| --- | --- | --- |
| `commandTimeoutS` | 180 s | 180 s |
| `outputChars` | 6,000 | 12,000 |
| `fileReadChars` | 160,000 | 160,000 |
| `writeChars` | 160,000 | 160,000 |
| `listEntries` | 100 | 100 |
| `exportBytes` | 8 MiB | 8 MiB |
| `exportBytesNode` | 64 MiB | 64 MiB |
| `ttl` | 86,400,000 ms (24 h) | 31,536,000,000 ms (365 days) |
| `pollMinMs` | 1,000 ms | 120,000 ms |
| `pollMaxMs` | 30,000 ms | 120,000 ms |
| `jobTimeoutMs` | 3,600,000 ms (1 h) | 86,400,000 ms (24 h) |
| `jobsPerSandbox` | 16 active | 64 active |
| `cleanupBatch` | 32 | 64 |

Fixed `LIMITS` include a 540,000 ms shared action budget, 10,000 ms cancellation
budget, 10 s background exec timeout, 1 s control-file acknowledgement wait,
0.1 s SIGTERM grace, 512 KiB export windows, 16,000-character commands,
4,096-character paths, and 256-character identities.

## Guarantees

- Lost create responses retain unknown [reservations](#registration-and-scope) without duplicate creates.
- Uncertain [commands and background launches](#five-tools) are not replayed.
- Interrupted launch/poll actions retain a [deadline watchdog](#background-completion).
- Successful [exports](#file-exports) retain exact bytes and SHA-256.

## Known limits

- The provider VM supplies isolation and network policy.
- Mounting arms no recurring cleanup timer. The host calls `sandbox.cleanup(ctx)` to schedule a finite sweep; active jobs protect files and action leases may delay idle cleanup by up to nine minutes. Deleted bindings remain tombstones; uncertain deletes and lost creates require operator reconciliation.
- Automatic core sandbox-slot and event-wait wiring remains a separate integration step. The host owns completion delivery and policy; no authoritative Daytona cost is available.
