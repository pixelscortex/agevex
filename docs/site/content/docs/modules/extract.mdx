## Setup

```ts title="convex/convex.config.ts"
import { defineApp } from "convex/server";
import agent from "@convex-dev/agent/convex.config";
import extract from "agevex/extract/convex.config";

const app = defineApp();
app.use(agent);
app.use(extract); // components.agevexExtract; includes its own Workflow
export default app;
```

```ts title="convex/files.ts"
import { defineExtract, directText, firecrawlParse, visionOcr } from "agevex/extract";
import type { WorkerArgs } from "agevex/extract";
import type { RegisteredAction, RegisteredQuery } from "convex/server";
import { components, internal } from "./_generated/api.js";
import { authorizeFileInThread } from "./filePolicy.js";
import { openai } from "@ai-sdk/openai";

const visionModel = openai("gpt-4.1-mini");

export const extract = defineExtract(components.agevexExtract, {
  agent: components.agent,
  worker: internal.files.execute,
  storageMetadata: internal.files.storageMetadata,
  authorize: authorizeFileInThread,
  backends: [
    directText(),
    firecrawlParse({ apiKey: () => process.env.FIRECRAWL_API_KEY! }),
    visionOcr({ model: visionModel }),
  ],
});

// Explicit types break generated-reference inference cycles.
const functions = extract.internalFunctions();
export const execute: RegisteredAction<"internal", WorkerArgs, null> = functions.execute;
export const storageMetadata: RegisteredQuery<
  "internal",
  { storageId: string },
  { size: number } | null
> = functions.storageMetadata;
```

The host supplies `authorizeFileInThread(ctx, scope)`. The policy must verify thread access, the
exact attachment when `fileId` is present, and namespace access when
`namespace` is present. Background `execute` calls may have no user session;
keep an exact attachment reference rather than scanning transcripts.

Helpers taking `ctx` run in host actions and require `threadId`. Export your
own authorized Convex wrappers; no public endpoints are generated.
`internalFunctions()` supplies the worker and the query reading native
`_storage` size metadata. Attach files returned by `fromUrl` before extraction.

For RAG, additionally mount the native component and add the following option
to the registration above. The host supplies an instantiated AI SDK v3/v4
embedding model matching the configured dimension.

```ts title="Optional RAG mount and registration"
// convex/convex.config.ts
import rag from "@convex-dev/rag/convex.config";
// Before export default app:
app.use(rag, { name: "extractRag" });

// convex/files.ts
import { openai } from "@ai-sdk/openai";
const embeddingModel = openai.embedding("text-embedding-3-small");

// Add to defineExtract options:
// rag: {
//   component: components.extractRag,
//   embedding: embeddingModel,
//   embeddingDimension: 1536,
//   chunk: { maxBytes: 8192 },
// },
```

Use a dedicated RAG mount/namespace containing only these bounded chunks.
The host authorizes namespaces; file search tools use `threadId` as namespace.

## Wire it into agevex

Pass `extract.slot()` to `registerAgent`. With the slot set, files attached through
`open`/`send({ files })` are no longer sent to the model as native file parts: the
first slice of each turn admits one durable extraction per attached file (the
module's own dedup makes replays and re-attachments free), and the model gets
`read_file` bound to its thread and subject. With `rag` and `autoIndex: true`
(default false) each file is also indexed into the thread's namespace once its
extraction is ready, and the model additionally gets `search_files`; without
`autoIndex` the slot never offers `search_files`, since nothing would fill the
namespace. Indexing happens in the extraction worker for a fresh extraction and
in `slot.run` for an existing one; a thread that attached a file while another
thread's extraction of the same bytes was still running is indexed by its next
`run`.

```ts title="convex/agents.ts"
import { registerAgent } from "agevex";
import { authorizeAttached, defineExtract, directText } from "agevex/extract";

export const extract = defineExtract(components.agevexExtract, {
  agent: components.agent,
  worker: internal.files.execute,
  storageMetadata: internal.files.storageMetadata,
  backends: [directText()],
  // Lazy: `runtime` and `extract` reference each other.
  authorize: authorizeAttached(() => runtime),
});
// The annotation breaks the circular type inference.
export const runtime: ReturnType<typeof registerAgent> = registerAgent(components.agevex, {
  agents: [main],
  extract: extract.slot(),
  // authorize, refs, ...
});
```

`authorizeAttached` is the agevex policy for `authorize`: every file operation must
carry the thread owner and pass `runtime.fileAttached` (an indexed exact-attachment
lookup, no scans); calls without a subject are denied. The slot passes the owner to
`run`, which stores it in the durable job's arguments, so the background worker
authorizes without a session or lookup. A refusal in the worker (file detached,
host error) fails the artifact as retryable `OBJECT_UNAVAILABLE`, never `unknown`.
`search`/`index` are allowed only in the thread's own namespace and recheck
each file; `search` skips a hit whose file is no longer attached; `fromUrl` is denied (write your own
`authorize` for it). Upload with `runtime.registerFile(...)` in your trusted upload
path. `read_file` returns `{ status }` until the extraction is `ready`; it never
starts one.

## API

Every helper taking `ctx` is async and uses a Convex action context.

### Registration and backends

- `defineExtract(component: ComponentApi, options: ExtractOptions)`: required options are `agent`, `backends`, `worker`, `storageMetadata` and `authorize`; optional options are `route`, `limits`, `usage`, `rag`, `autoIndex` (needs `rag`) and `node`.
- `extractNodeExport(component, options)`: from a `"use node"` file, returns the internal `{ execute, read }` actions registered as `options.node`.
- `directText(): ExtractBackend`: strict local UTF-8 decoding for `text/*` (including Markdown, HTML and CSV), `application/json`, `application/xml`, `application/csv` and `application/javascript`. Empty text fails; malformed UTF-8 is unreadable.
- `firecrawlParse({ apiKey }: { apiKey: string | (() => string) }): ExtractBackend`: one bounded Firecrawl v2 multipart Parse request for PDF, DOCX, PPTX or XLSX; its URL hook makes one scrape request for Markdown.
- `visionOcr({ model }: { model: LanguageModel }): ExtractBackend`: image MIME types; one AI SDK transcription request with `maxRetries: 0`. Its version includes provider/model id; truncated output is a paid failure.
- `extract.internalFunctions()`: returns `{ execute, storageMetadata }` for host exports.
- `new ExtractError(code: ExtractFailure)`: error carrying a closed failure code in `code`.

Routing uses explicit `backend`, then optional `route(file: FileInfo)`, then
the first backend whose `accepts` matches. The selected backend must accept the
file. Built-in ids are `direct-text`, `firecrawl-parse` and `vision-ocr`.
Optional `usage.record(ctx, event)` receives `threadId`, `backend`, numeric
`usage`, and optional `artifactId`/`fileId`.

Custom backends implement the exported contract; bump `version` to change identity:

```ts title="Backend contract"
type ExtractBackend = {
  id: string;
  version: string;
  accepts(file: Pick<FileInfo, "mimeType" | "byteSize">): boolean;
  run(input: BackendInput): Promise<BackendResult>;
  fromUrl?: (url: string, signal: AbortSignal) => Promise<BackendResult>;
};
type BackendInput = { bytes: () => Promise<Blob>; file: FileInfo; signal: AbortSignal };
type BackendResult =
  | { ok: true; doc: ExtractedDoc; usage?: ProviderUsage }
  | { ok: false; failure: ExtractFailure; usage?: ProviderUsage };
type ExtractedDoc = {
  kind: "text" | "document" | "image";
  text: string;
  pages?: { number: number; text: string }[];
  language?: string;
};
```

`FileInfo` contains `fileId`, `mimeType`, `byteSize`, `hash` and optional
`filename`. Lazy `bytes()` enforces size and SHA-256. Pages must be numbered
consecutively from 1. Validation strips unknown payload fields.

### Acquisition, extraction and reads

- `extract.fromUrl(ctx, { threadId, url })`: first backend with a URL hook fetches HTTP(S), records reported usage, and stores Markdown with native Agent `storeFile`; returns `{ fileId, usage? }`.
- `extract.run(ctx, { threadId, fileId, subject?, backend?, optionsHash?, onComplete? })`: atomically admits durable extraction; `subject` is forwarded to `authorize` and carried in the job arguments (not the artifacts table) for the worker; returns `{ artifactId, action: "run" | "wait" | "reuse", callback? }`. When no backend accepts the file (and none was requested explicitly) it records a terminal `failed` / `UNSUPPORTED_TYPE` artifact without any provider call and returns `reuse`, so an unsupported attachment never fails the turn.
- `extract.get(ctx, { threadId, fileId, backend?, optionsHash? } | { threadId, artifactId })`: returns an exact identity view or `null`; missing explicit artifact ids throw `OBJECT_UNAVAILABLE`.
- `extract.readText(ctx, { threadId, artifactId, cursor?, maxBytes? })`: returns `{ text, cursor: number | null, done }`; defaults to cursor 0 and a 1 MiB window.
- `extract.readPages(ctx, { threadId, artifactId, from?, count?, cursor?, maxBytes? })`: returns `{ pages, next: { from, cursor } | null }`; defaults to page 1, 100 pages, cursor 0 and 1 MiB aggregate text.
- `extract.release(ctx, { threadId, artifactId, namespace? })`: removes only the caller's namespace index (default `threadId`): fences it, deletes its native RAG entry by exact id and drops the record. The shared extraction and other namespaces' indexes are untouched; returns `null`.
- `extract.purge(ctx, { fileId })`: **admin operation**, performs no `authorize`; expose it only behind your own admin check. Agent dedupes uploads by hash, so every thread that attached the same bytes shares an extraction; purge tombstones all extractions of `fileId` for all of them (receipt and reported usage stay), fences late output and deletes their payload blobs. It also fences every namespace's index record of those extractions, deletes its native RAG entry by exact id and drops the record, so no chunks or vectors are orphaned. Work per call is bounded (at most `LIMITS.purgeBatch` = 32 index records) and nothing reschedules itself: returns `{ more }`; loop `do { r = await extract.purge(ctx, { fileId }); } while (r.more);`.

`onComplete` is an internal mutation reference taking `{ artifactId: string }`
and returning `null | void`; it runs after Workflow completion, including failed
work, and does not run again on reuse. Every `run` caller that passes it and gets `run` or `wait` (including re-admits after a queue deadline or a retryable failure) has its handle stored on the artifact: at most `LIMITS.callbacksPerArtifact` (4) distinct handles of at most `LIMITS.callbackBytes` (512). Whichever dispatch owns the artifact's claim when the workflow completes calls every stored handle exactly once and clears the list, so a caller whose dispatch was superseded still gets its callback. The admission result carries `callback: "stored" | "dropped"`; when the list is full the new handle is dropped and that caller must poll `get`. A `reuse` result is already terminal: no callback is stored or fired. Views contain `artifactId`, `fileId`,
`backend`, `version`, `optionsHash`, `status`, `attempt`, optional `summary`,
`failure: { code, retryable }`, and `usage`. Status is `pending`, `running`,
`ready`, `failed`, `unknown`, or `released`.

Reads require `ready`. Cursors are UTF-8 byte offsets; resume with the returned
cursor or spread page `next` into the next call. Page numbers are one-based;
a document without pages is exposed as one page. Large pages resume within the
page. Mid-character cursors throw `INVALID_EXTRACT_CURSOR`; a window too small
for the next character throws `EXTRACT_WINDOW_TOO_SMALL`.

### Optional RAG and tools

- `extract.index(ctx, { threadId, artifactId, namespace, key, automatic? })`: indexes ready artifact text; returns `{ entryId, status: "ready" | "pending" | "skipped", created, replacedEntry: null, usage: { tokens } }`; `entryId` may be absent while waiting. The index record is checked before the payload is loaded: a ready or live index returns without a payload read. With `automatic: true` (used by the slot and the worker) a missing record is created but an existing failed, unknown, released or key-changed one is `skipped`, never re-embedded.
- `extract.search(ctx, { threadId, namespace, query, limit? })`: returns `{ text, references: { artifactId, fileId }[], usage }`; defaults to 10 results, no adjacent chunk context, and at most 64 KiB text.
- `extract.tools({ ctx, threadId, subject? })`: returns AI SDK `read_file` and, only with RAG configured, `search_files`. `subject` is forwarded to `authorize`.
- `extract.slot(): ExtractSlot`: the agevex `extract` slot ([above](#wire-it-into-agevex)); `authorizeAttached(() => runtime)` builds the matching `authorize`.
- `read_file({ fileId, page?, cursor? })`: reads an existing ready artifact in 64 KiB windows with file/artifact references and `next` arguments; otherwise returns `{ status }` (`missing` when absent), plus `error` with the closed failure code for a failed artifact (for example `UNSUPPORTED_TYPE`). It does not start extraction.
- `search_files({ query })`: searches the thread namespace with the same text bound and references as `search`.

Index admission serializes work per (artifact, namespace). Live `cleaning`/`running` work
returns `pending`; completed matching namespace/key calls return `ready` with
zero new embedding tokens. Native entry creation and recording its exact id
commit atomically before embedding. Caller keys are scoped to artifact ids.
Because threads share extractions, each namespace has its own index record and
native entry: indexing, replacing, recovering or releasing one never touches
another's.

The independent indexing lease defaults to 10 minutes; lower it through
`limits.indexLeaseMs`.

| Index state / trigger | Outcome |
| --- | --- |
| Lease expires | Records `unknown`, retaining the exact entry id; the one-shot check neither reschedules nor starts paid work. |
| Explicit `index()` on failed, unknown or expired work | Claims a new lease, awaits exact-id deletion of the old entry, then creates a replacement. |
| Changed key in the same namespace | Replaces that namespace's old entry. |
| `release()` | Fences the record, deletes its entry, then drops the record; a crash in between is finished by a repeated `release` or the next `index`. |

Claim and lease checks fence entry
creation, chunk writes and promotion, including late writers. A paid embedding is
never discarded because the file was detached meanwhile: the index is published
and `search` re-authorizes every hit, skipping files no longer attached, so a
re-attach is searchable without embedding again. After `release` the record is
gone, so a re-attach under `autoIndex` indexes that thread again. Search returns
only current ready indexes of ready artifacts.
Failed embedding requests are not automatically retried.

### Artifacts and failures

Extract owns two tables. `artifacts` is indexed by
`(fileId, backend, version, optionsHash)` (and by `fileId` for `purge`) and owns
attempts rather than writing core receipts. `indexes`, used only with RAG, holds one
row per `(artifact, namespace)`. Native Agent owns files, host storage owns JSON payloads, the
nested Workflow owns its journal, and native RAG owns chunks/vectors.

| Artifact fields | Purpose |
| --- | --- |
| `_id`, `_creationTime` | Convex identity and creation metadata |
| `fileId`, `backend`, `version`, `optionsHash` | Exact extraction identity |
| `status`, `attempt`, `claim`, `leaseUntil` | Admission, dispatch, completion and expiry fences. `leaseUntil` is the queue deadline while `pending` and the running lease from `start` |
| `summary` | `kind`, `textBytes`, `pages`, `preview`, optional `language` |
| `payloadStorageId` | Exact host-storage JSON reference and cleanup |
| `failure` | Optional closed failure code |
| `usage` | Optional numeric `inputTokens`, `outputTokens`, `credits` |
| `callbacks` | Distinct completion callback handles of every admitter, fired once by the owning dispatch and cleared |

| Index fields (`indexes`) | Purpose |
| --- | --- |
| `artifactId`, `namespace` | The shared extraction and the indexing target |
| `key` | Target reuse |
| `status`, `claim`, `leaseUntil` | `cleaning \| running \| unknown \| failed \| ready \| released`: lifecycle, stale-writer fence and lease |
| `entryId` | Exact native entry cleanup and search filtering |

No provider bodies, request content, ownership copies or vectors enter either table.

| Closed failure code | `retryable` |
| --- | --- |
| `UNSUPPORTED_TYPE` | false |
| `UNREADABLE` | false |
| `EMPTY` | false |
| `INVALID_OUTPUT` | false |
| `TOO_LARGE` | false |
| `PROVIDER_UNAVAILABLE` | true |
| `OBJECT_UNAVAILABLE` | true |
| `CHECKSUM_FAILED` | true |

Admission follows `reuse | wait | run(attempt + 1)`. A `failed` artifact with a
retryable code is run again as the next attempt by an explicit `run`, at most
`LIMITS.maxAttempts` (3) in total; the last failure is final. Nothing retries by
itself, failed attempts' usage accumulates on the row, and final failures,
`ready`, `unknown` and `released` identities are reused. A `pending` artifact has
done no paid work: it waits up to `LIMITS.queueMs` (10 minutes), after which an
admission dispatches it again under a new claim (the stale dispatch can no longer
start). The running lease starts when the worker starts, never at admission.
Ambiguous extraction outcomes (a started attempt whose lease expires or whose
worker crashes) become `unknown`, without inventing a failure code, and are never rerun.
Separate argument/state errors include `INVALID_EXTRACT_ARGUMENT`,
`DUPLICATE_EXTRACT_BACKEND`, `EXTRACT_AUTHORIZE_REQUIRED`,
`EXTRACT_MODEL_INSTANCE_REQUIRED`, `EXTRACT_NOT_READY`,
`EXTRACT_RAG_DISABLED`, and `EXTRACT_INDEX_FENCED`.

## Limits

Values come from exported `LIMITS`. Text byte limits use UTF-8; MiB/KiB are
binary. Only `limits.maxBytes`, `limits.payloadBytes`, and
`limits.indexLeaseMs` are registration overrides: positive integers no larger
than their hard maxima. The byte ceilings depend on the runtime:

- **Default Convex runtime (64 MiB)**: document 12 MiB, image 6 MiB, text 4 MiB,
  payload 6 MiB.
- **Opt-in Node runtime (512 MiB)**: document 50,000,000, image 10,000,000, text
  8 MiB, payload 32 MiB.

Arithmetic (16 MiB reserved for code and runtime; every live copy counted, no GC
timing assumed; N input bytes, P payload bytes): Firecrawl request phase `3N`
(Blob, request body, fetch buffer) and vision OCR `6N` (Blob, bytes, ~3 base64 copies
of 4/3 N each); output phase `N + 6P` (cached Blob, response chunks + merge, decoded
string, parsed object); direct text `4N + 3P` (blob, bytes, decoded string, JSON string, output Blob);
reads `6P`. Default: 36, 36, 34, 48 and
36 MiB, within the 48 MiB working set. Node: 150 MB, 60 MB, 128 MiB, 242 MB and
192 MiB, within 496 MiB. The checksum is streamed, adding no whole-file copy. Before `JSON.stringify`, the
exact serialized size is computed without allocating (control characters escape
to up to six bytes, `"` and `\` to two, and one non-Latin-1 character makes the
string two-byte), and an over-ceiling result is `TOO_LARGE` first; unguarded, a
4 MiB control-character text would build a 48 MiB string.

To extract larger files, export the Node actions from a `"use node"` file and
register them:

```ts title="convex/filesNode.ts"
"use node";
import { extractNodeExport } from "agevex/extract";
import { components } from "./_generated/api.js";
import { extractOptions } from "./extractOptions.js";

export const { execute, read } = extractNodeExport(components.agevexExtract, extractOptions);
// extractOptions: node: { execute: internal.filesNode.execute, read: internal.filesNode.read }
```

With `node` registered, the limit maxima rise to the Node values; files above the
default ceiling are dispatched to the Node `execute` at admission, and payloads
above the default read ceiling are windowed by the Node `read` (both repeat
authorization). Without it, an oversized file is recorded as `TOO_LARGE` before
any provider is called.

| Limit | Default | Hard maximum / constraint |
| --- | --- | --- |
| `maxBytes.document` | 12 MiB (Node 50,000,000) | same |
| `maxBytes.image` | 6 MiB (Node 10,000,000) | same |
| `maxBytes.text` | 4 MiB (Node 8 MiB) | same |
| `payloadBytes` | 6 MiB (Node 32 MiB) | same, serialized JSON |
| `readBytes` / `pages` | 1 MiB / 100 | Both ceilings per page window |
| `totalPages` | — | 10,000 per payload |
| `toolBytes` | 64 KiB | Text per tool/search response |
| `summaryBytes` | — | 1,024-byte preview |
| `identifierBytes` / `hashBytes` | — | 256 bytes / 64 lowercase SHA-256 hex characters |
| `urlBytes` / `queryBytes` | — | 4,096 bytes each |
| `backends` | Host-supplied | 1–32, unique ids |
| `leaseMs` / `queueMs` | 600,000 ms / 600,000 ms | Running lease (from `start`) / queue deadline before re-dispatch |
| `maxAttempts` | 3 | Hard bound on explicit retryable-failure retries |
| `callbacksPerArtifact` / `callbackBytes` | 4 / 512 bytes | Distinct completion callbacks stored per artifact / handle size |
| `indexLeaseMs` | 600,000 ms | 600,000 ms; minimum 1 ms |
| `providerMs` / `outputTokens` | 300,000 ms / 4,096 | Backend signal deadline / OCR output cap |
| `searchResults` | 10 | 10; minimum 1 |
| `indexBytes` / `indexChunks` | — | 1 MiB text / 1,024 chunks |
| `chunkBytes` / `minChunkBytes` | 8,192 bytes | Configured chunk size 1,024–8,192 bytes |
| `ragBatch` | 100 chunks | 100 per native write batch |
| `embeddingDimension` | Host-required | 4,096; supported: 128, 256, 512, 768, 1024, 1408, 1536, 2048, 3072, 4096 |

## Guarantees

- Concurrent [extraction](#acquisition-extraction-and-reads) admission and duplicate dispatch do not repeat provider work for the same identity.
- A queued extraction never expires unpaid, and retryable failures are retried only by explicit admission, at most three times.
- One thread's index, replacement or release never touches another thread's index of the same shared extraction.
- Extraction lease expiry fences late publication, retains paid usage and never reclaims expired work; see [artifact states](#artifacts-and-failures).
- [Authorization](#setup) runs before reads and before backend work (a refusal is retryable). A paid provider result is published even if the file was detached mid-run, since every read re-authorizes; discarding it would pay again.
- Automatic indexing (`autoIndex`, via `index({ automatic: true })`) only creates a missing index record and never re-embeds a failed, unknown or replaced one; only an explicit `index()` recovers those.
- [Payload and RAG bounds](#limits) are exercised under transaction limits.
- [Completion callbacks](#acquisition-extraction-and-reads) observe saved terminal results even if a usage hook fails; hook failure cannot replay provider work.

## Known limits

- Hosts supply action wrappers, authorization, exact attachment records, worker/metadata exports and `tools({ ctx, threadId })` wiring (or `extract.slot()` under agevex).
- Final-failed (or out-of-attempts), released and unknown extraction identities are reused without rerunning. Intentionally change a backend version or supply a different valid SHA-256 `optionsHash` to request new work. The default hash covers resolved extraction ceilings, excluding the indexing lease.
- Windowed reads still load and parse the bounded full JSON payload in an action (one decode, no schema copy). Indexing covers only `doc.text`, up to 1 MiB, even when a larger artifact is readable.
- A dedicated RAG mount/namespace is required for chunk bounds. `release` deletes one namespace's native entry; `purge` deletes the RAG entries of every namespace that indexed the file. Prior-index cleanup happens on explicit replacement/recovery.
- Built-in Firecrawl transport makes one request per operation. Custom backends must uphold their own provider retry and signal behavior.
