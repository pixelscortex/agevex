Extract turns native Agent files into storage-backed text and pages. Use it for
readable attachments or thread-isolated search. Its Convex component owns
`artifacts`, `indexes` and an id-only Workflow. Host actions authorize files,
call extraction/embedding providers and store payloads. Native RAG owns vectors.

## Wire it into agevex

Install the [built package and peers](/docs/getting-started). Direct text needs
no additional provider package. Mount extract as `agevexExtract`:

```ts title="convex/convex.config.ts"
import { defineApp } from "convex/server";
import agent from "@convex-dev/agent/convex.config";
import agevex from "agevex/convex.config";
import extract from "agevex/extract/convex.config";

const app = defineApp();
app.use(agent, { name: "agent" });
app.use(agevex, { name: "agevex" });
app.use(extract, { name: "agevexExtract" });
export default app;
```

Define worker and storage metadata exports. This policy accepts only exact
subject/thread/file attachments already recorded by core:

```ts title="convex/files.ts"
import { authorizeAttached, defineExtract, directText } from "agevex/extract";
import { components, internal } from "./_generated/api.js";
import { runtime } from "./agents.js";

export const extract = defineExtract(components.agevexExtract, {
  agent: components.agent,
  backends: [directText()],
  worker: internal.files.execute,
  storageMetadata: internal.files.storageMetadata,
  authorize: authorizeAttached(() => runtime),
});
export const { execute, storageMetadata } = extract.internalFunctions();
```

Replace `convex/agents.ts` from [getting started](/docs/getting-started), keeping
its `agentConfig.ts`:

```ts title="convex/agents.ts"
import { registerAgent } from "agevex";
import { components } from "./_generated/api.js";
import { registration } from "./agentConfig.js";
import { extract } from "./files.js";

export const runtime = registerAgent(components.agevex, {
  ...registration,
  extract: extract.slot(),
});
export const { runTurn, coordinate, textTask } = runtime.internalFunctions();
export const {
  open,
  send,
  cancel,
  respond,
  answer,
  messages,
  streams,
  activity,
  runTree,
  delegations,
} = runtime.authorizedEndpoints();
```

In a trusted upload mutation, call `runtime.registerFile` with the owner,
agent and native file id. Then attach that id through `open` or `send`.
Core admits each attachment on the first slice and binds `read_file` to its
thread. `authorizeAttached` denies calls without a subject, foreign namespaces
and URL acquisition. Supply a separate host policy if you need `fromUrl`.

## Extraction and indexing

An identity is `fileId + backend + version + optionsHash`. Admission returns
`run`, `wait` or `reuse`. A queued dispatch can be replaced before paid
work starts. A started attempt that crashes or loses its lease becomes unknown
and never reruns automatically. Explicit `run` may retry a known retryable
failure, up to three attempts. Ready, unknown, released and final-failed
identities are reused. Change backend version or a valid SHA-256 options hash
to request a new identity intentionally.

`get` returns metadata. `readText` and `readPages` return bounded windows
from the storage payload. Reads and backend execution repeat authorization.
Paid output is published even if the attachment changes during extraction;
subsequent reads recheck access.

For search, mount a dedicated native RAG component and supply `rag` with an
embedding model instance and dimension. `autoIndex: true` enables the slot's
`search_files`. Each thread uses its own namespace; every hit rechecks the
current artifact/index and exact attachment. Automatic indexing only creates a
missing index. Explicit indexing can recover failed or unknown index work.
`release` removes one namespace entry. Admin-only `purge` removes shared
payload/index content in bounded calls while retaining admission receipts.

## Limits

Only `maxBytes`, `payloadBytes` and `indexLeaseMs` are configurable.
Byte bounds use UTF-8.

| Bound                                      | Default Convex runtime  | Opt-in Node runtime                   |
| ------------------------------------------ | ----------------------- | ------------------------------------- |
| Document / image / text input              | 12 / 6 / 4 MiB          | 50,000,000 / 10,000,000 bytes / 8 MiB |
| Serialized payload                         | 6 MiB                   | 32 MiB                                |
| Read window                                | 1 MiB and 100 pages     | Same                                  |
| Tool output                                | 64 KiB                  | Same                                  |
| Index text / chunks                        | 1 MiB / 1,024           | Same                                  |
| Search results                             | At most 10              | Same                                  |
| Running lease / queue deadline             | 10 minutes / 10 minutes | Same                                  |
| Backends / attempts / completion callbacks | 32 / 3 / 4              | Same                                  |

Export `extractNodeExport(component, options)` from a host `"use node"`
file, then register its `execute` and `read` references in `options.node`
for larger ceilings. Windowed reads still parse the bounded full JSON payload.
Firecrawl and vision OCR are optional backends; provider calls must honor their
signal and must not retry unknown paid outcomes. See the
[module README](https://github.com/pixelscortex/agevex/blob/HEAD/src/modules/extract/README.md).
