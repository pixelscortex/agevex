## Setup

```ts title="convex/convex.config.ts"
import { defineApp } from "convex/server";
import agent from "@convex-dev/agent/convex.config";
import extract from "agevex/extract/convex.config";

const app = defineApp();
app.use(agent);
app.use(extract); // components.agevexExtract; includes its own Workflow
export default app;
```

```ts title="convex/files.ts"
import { defineExtract, directText, firecrawlParse, visionOcr } from "agevex/extract";
import type { WorkerArgs } from "agevex/extract";
import type { RegisteredAction, RegisteredQuery } from "convex/server";
import { components, internal } from "./_generated/api.js";
import { authorizeFileInThread } from "./filePolicy.js";
import { openai } from "@ai-sdk/openai";

const visionModel = openai("gpt-4.1-mini");

export const extract = defineExtract(components.agevexExtract, {
  agent: components.agent,
  worker: internal.files.execute,
  storageMetadata: internal.files.storageMetadata,
  authorize: authorizeFileInThread,
  backends: [
    directText(),
    firecrawlParse({ apiKey: () => process.env.FIRECRAWL_API_KEY! }),
    visionOcr({ model: visionModel }),
  ],
});

// Explicit types break generated-reference inference cycles.
const functions = extract.internalFunctions();
export const execute: RegisteredAction<"internal", WorkerArgs, null> = functions.execute;
export const storageMetadata: RegisteredQuery<
  "internal",
  { storageId: string },
  { size: number } | null
> = functions.storageMetadata;
```

The host supplies `authorizeFileInThread(ctx, scope)`. The policy must verify thread access, the
exact attachment when `fileId` is present, and namespace access when
`namespace` is present. Background `execute` calls may have no user session;
keep an exact attachment reference rather than scanning transcripts.

Helpers taking `ctx` run in host actions and require `threadId`. Export your
own authorized Convex wrappers; no public endpoints are generated.
`internalFunctions()` supplies the worker and the query reading native
`_storage` size metadata. Attach files returned by `fromUrl` before extraction.

For RAG, additionally mount the native component and add the following option
to the registration above. The host supplies an instantiated AI SDK v3/v4
embedding model matching the configured dimension.

```ts title="Optional RAG mount and registration"
// convex/convex.config.ts
import rag from "@convex-dev/rag/convex.config";
// Before export default app:
app.use(rag, { name: "extractRag" });

// convex/files.ts
import { openai } from "@ai-sdk/openai";
const embeddingModel = openai.embedding("text-embedding-3-small");

// Add to defineExtract options:
// rag: {
//   component: components.extractRag,
//   embedding: embeddingModel,
//   embeddingDimension: 1536,
//   chunk: { maxBytes: 8192 },
// },
```

Use a dedicated RAG mount/namespace containing only these bounded chunks.
The host authorizes namespaces; file search tools use `threadId` as namespace.

## Wire it into agevex

Pass `extract.slot()` to `registerAgent`. With the slot set, files attached through
`open`/`send({ files })` are no longer sent to the model as native file parts: the
first slice of each turn admits one durable extraction per attached file (the
module's own dedup makes replays and re-attachments free), and the model gets
`read_file` (and `search_files` with RAG) bound to its thread and subject.

```ts title="convex/agents.ts"
import { registerAgent } from "agevex";
import { authorizeAttached, defineExtract, directText } from "agevex/extract";

export const extract = defineExtract(components.agevexExtract, {
  agent: components.agent,
  worker: internal.files.execute,
  storageMetadata: internal.files.storageMetadata,
  backends: [directText()],
  // Lazy: `runtime` and `extract` reference each other.
  authorize: authorizeAttached(() => runtime, components.agevex),
});
// The annotation breaks the circular type inference.
export const runtime: ReturnType<typeof registerAgent> = registerAgent(components.agevex, {
  agents: [main],
  extract: extract.slot(),
  // authorize, refs, ...
});
```

`authorizeAttached` is the agevex policy for `authorize`: files must be attached to
the exact thread (`runtime.fileAttached`, an indexed lookup, no scans) for the
thread's own subject; thread-level operations need a matching `subject`, and the
search namespace must equal the thread id. The durable worker has no session, so
the owner is read from the thread's assignment. Upload with
`runtime.registerFile(...)` in your trusted upload path. `read_file` returns
`{ status }` until the extraction is `ready`; it never starts one.

## API

Every helper taking `ctx` is async and uses a Convex action context.

### Registration and backends

- `defineExtract(component: ComponentApi, options: ExtractOptions)`: required options are `agent`, `backends`, `worker`, `storageMetadata` and `authorize`; optional options are `route`, `limits`, `usage` and `rag`.
- `directText(): ExtractBackend`: strict local UTF-8 decoding for `text/*` (including Markdown, HTML and CSV), `application/json`, `application/xml`, `application/csv` and `application/javascript`. Empty text fails; malformed UTF-8 is unreadable.
- `firecrawlParse({ apiKey }: { apiKey: string | (() => string) }): ExtractBackend`: one bounded Firecrawl v2 multipart Parse request for PDF, DOCX, PPTX or XLSX; its URL hook makes one scrape request for Markdown.
- `visionOcr({ model }: { model: LanguageModel }): ExtractBackend`: image MIME types; one AI SDK transcription request with `maxRetries: 0`. Its version includes provider/model id; truncated output is a paid failure.
- `extract.internalFunctions()`: returns `{ execute, storageMetadata }` for host exports.
- `new ExtractError(code: ExtractFailure)`: error carrying a closed failure code in `code`.

Routing uses explicit `backend`, then optional `route(file: FileInfo)`, then
the first backend whose `accepts` matches. The selected backend must accept the
file. Built-in ids are `direct-text`, `firecrawl-parse` and `vision-ocr`.
Optional `usage.record(ctx, event)` receives `threadId`, `backend`, numeric
`usage`, and optional `artifactId`/`fileId`.

Custom backends implement the exported contract; bump `version` to change identity:

```ts title="Backend contract"
type ExtractBackend = {
  id: string;
  version: string;
  accepts(file: Pick<FileInfo, "mimeType" | "byteSize">): boolean;
  run(input: BackendInput): Promise<BackendResult>;
  fromUrl?: (url: string, signal: AbortSignal) => Promise<BackendResult>;
};
type BackendInput = { bytes: () => Promise<Blob>; file: FileInfo; signal: AbortSignal };
type BackendResult =
  | { ok: true; doc: ExtractedDoc; usage?: ProviderUsage }
  | { ok: false; failure: ExtractFailure; usage?: ProviderUsage };
type ExtractedDoc = {
  kind: "text" | "document" | "image";
  text: string;
  pages?: { number: number; text: string }[];
  language?: string;
};
```

`FileInfo` contains `fileId`, `mimeType`, `byteSize`, `hash` and optional
`filename`. Lazy `bytes()` enforces size and SHA-256. Pages must be numbered
consecutively from 1. Validation strips unknown payload fields.

### Acquisition, extraction and reads

- `extract.fromUrl(ctx, { threadId, url })`: first backend with a URL hook fetches HTTP(S), records reported usage, and stores Markdown with native Agent `storeFile`; returns `{ fileId, usage? }`.
- `extract.run(ctx, { threadId, fileId, backend?, optionsHash?, onComplete? })`: atomically admits durable extraction; returns `{ artifactId, action: "run" | "wait" | "reuse" }`.
- `extract.get(ctx, { threadId, fileId, backend?, optionsHash? } | { threadId, artifactId })`: returns an exact identity view or `null`; missing explicit artifact ids throw `OBJECT_UNAVAILABLE`.
- `extract.readText(ctx, { threadId, artifactId, cursor?, maxBytes? })`: returns `{ text, cursor: number | null, done }`; defaults to cursor 0 and a 1 MiB window.
- `extract.readPages(ctx, { threadId, artifactId, from?, count?, cursor?, maxBytes? })`: returns `{ pages, next: { from, cursor } | null }`; defaults to page 1, 100 pages, cursor 0 and 1 MiB aggregate text.
- `extract.release(ctx, { threadId, artifactId })`: marks the identity released, deletes its payload blob if present, and fences late output; returns `null`.

`onComplete` is an internal mutation reference taking `{ artifactId: string }`
and returning `null | void`; it runs after Workflow completion, including failed
work, and does not run again on reuse. Views contain `artifactId`, `fileId`,
`backend`, `version`, `optionsHash`, `status`, `attempt`, optional `summary`,
`failure: { code, retryable }`, and `usage`. Status is `pending`, `running`,
`ready`, `failed`, `unknown`, or `released`.

Reads require `ready`. Cursors are UTF-8 byte offsets; resume with the returned
cursor or spread page `next` into the next call. Page numbers are one-based;
a document without pages is exposed as one page. Large pages resume within the
page. Mid-character cursors throw `INVALID_EXTRACT_CURSOR`; a window too small
for the next character throws `EXTRACT_WINDOW_TOO_SMALL`.

### Optional RAG and tools

- `extract.index(ctx, { threadId, artifactId, namespace, key })`: indexes ready artifact text; returns `{ entryId, status: "ready" | "pending", created, replacedEntry: null, usage: { tokens } }`; `entryId` may be absent while waiting.
- `extract.search(ctx, { threadId, namespace, query, limit? })`: returns `{ text, references: { artifactId, fileId }[], usage }`; defaults to 10 results, no adjacent chunk context, and at most 64 KiB text.
- `extract.tools({ ctx, threadId, subject? })`: returns AI SDK `read_file` and, only with RAG configured, `search_files`. `subject` is forwarded to `authorize`.
- `extract.slot(): ExtractSlot`: the agevex `extract` slot ([above](#wire-it-into-agevex)); `authorizeAttached(() => runtime, components.agevex)` builds the matching `authorize`.
- `read_file({ fileId, page?, cursor? })`: reads an existing ready artifact in 64 KiB windows with file/artifact references and `next` arguments; otherwise returns `{ status }` (`missing` when absent). It does not start extraction.
- `search_files({ query })`: searches the thread namespace with the same text bound and references as `search`.

Index admission serializes work per artifact. Live `cleaning`/`running` work
returns `pending`; completed matching namespace/key calls return `ready` with
zero new embedding tokens. Native entry creation and recording its exact id
commit atomically before embedding. Caller keys are scoped to artifact ids.

The independent indexing lease defaults to 10 minutes; lower it through
`limits.indexLeaseMs`.

| Index state / trigger | Outcome |
| --- | --- |
| Lease expires | Records `unknown`, retaining the exact entry id; the one-shot check neither reschedules nor starts paid work. |
| Explicit `index()` on failed, unknown or expired work | Claims a new lease, awaits exact-id deletion of the old entry, then creates a replacement. |
| Changed namespace/key | Replaces the old entry. |

Claim and lease checks fence entry
creation, chunk writes and promotion, including late writers. Search rechecks
attachments and returns only current ready indexes of ready artifacts.
Failed embedding requests are not automatically retried.

### Artifacts and failures

The only Extract-owned table is `artifacts`, indexed by
`(fileId, backend, version, optionsHash)`. It owns attempts rather than writing
core receipts. Native Agent owns files, host storage owns JSON payloads, the
nested Workflow owns its journal, and native RAG owns chunks/vectors.

| Artifact fields | Purpose |
| --- | --- |
| `_id`, `_creationTime` | Convex identity and creation metadata |
| `fileId`, `backend`, `version`, `optionsHash` | Exact extraction identity |
| `status`, `attempt`, `claim`, `leaseUntil` | Admission, dispatch, completion and expiry fences |
| `summary` | `kind`, `textBytes`, `pages`, `preview`, optional `language` |
| `payloadStorageId` | Exact host-storage JSON reference and cleanup |
| `failure` | Optional closed failure code |
| `usage` | Optional numeric `inputTokens`, `outputTokens`, `credits` |
| `indexStatus`, `indexClaim`, `indexLeaseUntil` | Independent indexing lifecycle and fence |
| `indexEntryId`, `indexNamespace`, `indexKey` | Exact entry cleanup, target reuse and search filtering |

`indexStatus` is optional or `cleaning | running | unknown | failed | ready`.
No provider bodies, request content, ownership copies or vectors enter this table.

| Closed failure code | `retryable` |
| --- | --- |
| `UNSUPPORTED_TYPE` | false |
| `UNREADABLE` | false |
| `EMPTY` | false |
| `INVALID_OUTPUT` | false |
| `TOO_LARGE` | false |
| `PROVIDER_UNAVAILABLE` | true |
| `OBJECT_UNAVAILABLE` | true |
| `CHECKSUM_FAILED` | true |

`retryable` classifies the cause; it never permits automatic paid replay.
Ambiguous extraction outcomes become `unknown`, without inventing a failure code.
Separate argument/state errors include `INVALID_EXTRACT_ARGUMENT`,
`DUPLICATE_EXTRACT_BACKEND`, `EXTRACT_AUTHORIZE_REQUIRED`,
`EXTRACT_MODEL_INSTANCE_REQUIRED`, `EXTRACT_NOT_READY`,
`EXTRACT_RAG_DISABLED`, and `EXTRACT_INDEX_FENCED`.

## Limits

Values come from exported `LIMITS`. Text byte limits use UTF-8; MiB/KiB are
binary. Only `limits.maxBytes`, `limits.payloadBytes`, and
`limits.indexLeaseMs` are registration overrides: positive integers no larger
than their hard maxima.

| Limit | Default | Hard maximum / constraint |
| --- | --- | --- |
| `maxBytes.document` | 50,000,000 bytes | 50,000,000 bytes |
| `maxBytes.image` | 10,000,000 bytes | 10,000,000 bytes |
| `maxBytes.text` | 8 MiB | 8 MiB |
| `payloadBytes` | 32 MiB | 32 MiB serialized JSON |
| `readBytes` / `pages` | 1 MiB / 100 | Both ceilings per page window |
| `totalPages` | — | 10,000 per payload |
| `toolBytes` | 64 KiB | Text per tool/search response |
| `summaryBytes` | — | 1,024-byte preview |
| `identifierBytes` / `hashBytes` | — | 256 bytes / 64 lowercase SHA-256 hex characters |
| `urlBytes` / `queryBytes` | — | 4,096 bytes each |
| `backends` | Host-supplied | 1–32, unique ids |
| `leaseMs` | 600,000 ms | Fixed extraction lease |
| `indexLeaseMs` | 600,000 ms | 600,000 ms; minimum 1 ms |
| `providerMs` / `outputTokens` | 300,000 ms / 4,096 | Backend signal deadline / OCR output cap |
| `searchResults` | 10 | 10; minimum 1 |
| `indexBytes` / `indexChunks` | — | 1 MiB text / 1,024 chunks |
| `chunkBytes` / `minChunkBytes` | 8,192 bytes | Configured chunk size 1,024–8,192 bytes |
| `ragBatch` | 100 chunks | 100 per native write batch |
| `embeddingDimension` | Host-required | 4,096; supported: 128, 256, 512, 768, 1024, 1408, 1536, 2048, 3072, 4096 |

## Guarantees

- Concurrent [extraction](#acquisition-extraction-and-reads) admission and duplicate dispatch do not repeat provider work for the same identity.
- Extraction lease expiry fences late publication, retains paid usage and never reclaims expired work; see [artifact states](#artifacts-and-failures).
- [Authorization](#setup) runs before reads and before/after backend work; ownership loss prevents publication.
- [Payload and RAG bounds](#limits) are exercised under transaction limits.
- [Completion callbacks](#acquisition-extraction-and-reads) observe saved terminal results even if a usage hook fails; hook failure cannot replay provider work.

## Known limits

- Hosts supply action wrappers, authorization, exact attachment records, worker/metadata exports and `tools({ ctx, threadId })` wiring (or `extract.slot()` under agevex).
- Failed, released and unknown extraction identities are reused without rerunning. Intentionally change a backend version or supply a different valid SHA-256 `optionsHash` to request new work. The default hash covers resolved extraction ceilings, excluding the indexing lease.
- Windowed reads still load and parse the bounded full JSON payload in an action. Indexing covers only `doc.text`, up to 1 MiB, even when a larger artifact is readable.
- A dedicated RAG mount/namespace is required for chunk bounds. Release hides indexed results through artifact checks; it does not delete native RAG entries. Prior-index cleanup happens on explicit replacement/recovery.
- Built-in Firecrawl transport makes one request per operation. Custom backends must uphold their own provider retry and signal behavior.
