---
title: Todo
description: A bounded, durable todo list owned by a thread.
---

```sh
bunx shadcn add http://localhost:3000/r/todo.json
```

Start the docs site first, or replace the origin with your registry host.
The item copies three files into `convex/agevexTools/`; it does not overwrite
your schema. It requires the host's existing `agevex` installation and installs
`ai`, `convex` and `zod`.

```ts title="convex/schema.ts"
import { defineSchema } from "convex/server";
import { todoTables } from "./agevexTools/todoSchema.js";

export default defineSchema({ ...todoTables }); // merge your existing tables
```

```ts title="In your agevex Agent registration"
import { createTodoTools } from "./agevexTools/todo.js";
import { internal } from "./_generated/api.js";

const tools = createTodoTools(internal.agevexTools.todoState);
// Include ...tools in your Agent's tools, then registerAgent with your host
// authorize and authorizeExecution policies as usual.
```

`todo_read({})` returns `{ todos }`, initially an empty array.
`todo_write({ todos })` replaces the whole list; an empty array clears it.
An item is `{ id: string, text: string, done: boolean }`. IDs must be unique.

The fixed `TODO_LIMITS` allow 100 items, 100 characters per ID, 4000 characters
per text, and **32 KiB of serialized UTF-8 for the entire list**. All apply
together. Owner and thread strings are at most 1024 characters. Unknown input
fields, including model-supplied ownership, are rejected.

The host table `agevexTodos` stores only `subject` and `threadId` (the composite
lookup/ownership scope) and `todos` (read and replaced by the tools). State
persists across runs in that thread. Each operation reads at most two indexed
rows to enforce uniqueness; one valid row is at most 41 KiB. There are no native
message reads or SDK tables. The host owns deletion and retention.

These are ordinary AI SDK tools built with core `defineOnceTool`. Core supplies
the trusted `ToolContext`, fences writes on cancellation, and replays each
`toolCallId` result. Reusing a call ID with different input returns `KEY_CONFLICT`;
unknown outcomes are not retried. New calls use new IDs, including fresh reads.
The internal state functions must stay internal: never expose them directly as
public endpoints that accept an arbitrary subject.
